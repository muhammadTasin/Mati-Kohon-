# Six requested improvements

This is an implementation and verification record, not a claim of field validation or a guaranteed competition result.

1. **Three reproducible comparisons:** `scripts/evaluate_full_system.ts`, `research/evaluation/full_system_comparison.json`, `test_evidence.mjs`. Current/calendar/full results, three displayed alternatives, individual source removals, modeled irrigation, window/constraint flags, input sensitivity and explicit abstention. Negative and unchanged results are retained. The temporal pilot and haor seasonal audits provide separate evidence with distinct limits.
2. **Consequential uncertainty:** `packages/rotation-engine/src/input_sensitivity.ts`, `experiments.ts`, `test_input_sensitivity.ts`. Costs, dates, winter soil water and salinity are perturbed under fixed preferences; the selector reruns. API and shared narration enforce review/insufficient-evidence outcomes. Score-neutralization checks remain separately labeled.
3. **Claims audit:** `docs/claims-register.json` links 18 claims to calculation, source, assumptions and permitted wording. Water/groundwater, soil, NISAR, coverage, source count, salinity, income, pesticides, freshness and validation limits are covered. Public headline wording, historical greenness explanation and erosion example metadata were corrected.
4. **Narration and freshness:** approved whole-message templates and style-only optional model output, with adversarial checks in `test_reliability.ts`. Independent source dates and forecast windows are screened; stale/future inputs and mixed-sensor recession slopes cannot authorize current advice.
5. **Focused demonstration:** `/judge/index.html`, three bilingual scenarios, dated report, source removals and trade-offs, review rehearsal, Bangla/English message, device speech and transcript fallback, scoped offline cache. Landing CTA leads here; comparison screens suppress the companion overlay. No real calls or messages are made by the walkthrough.
6. **Drainage connection:** `research/live/drainage.py`, `research/evaluation/drainage_evaluation.py`, `tests/test_drainage_evaluation.py`, engine land-readiness integration. Prefix-only backtests, recent-trend and last-year baselines, censored outcomes, method/sampling date ranges, field checks and provisional crop-feasibility changes. Limited pilot outcomes and unfavorable baseline comparisons are disclosed.

Reproduce: `npm run evaluate:all`, `npm test`, `npm run test:evaluation`. Node 22 and Python 3.10+ are sufficient for these committed evaluations; no credentials or new remote data are required. Evaluation artifacts include source hashes. CI runs the checks and uploads the five reports.

External evidence remains unfinished by definition: farmer/officer comprehension testing, independent field salinity and workability observations, actual irrigation/cost/yield outcomes, prospective forecast evaluation and submission review. These require real participants or observations; they have not been replaced with synthetic success claims.
